# 水下考古潜水记录 · 潮汐窗口与安全余压闭环

直接打开 `index.html` 使用（纯前端，数据存于浏览器 localStorage，无需构建、无第三方依赖）。
规则层测试：`npm test`（Node ≥ 18）。

## 闭环流程

1. **潜次登记**：计划开始/结束时段、主潜员与两名潜伴、潮高、起返（余）压。
2. **闭潜安全闸门**：核对实际出水时间后闭潜。以下任一不满足时**不得闭潜**，标记只能停留在待复核前置态：
   - 潮高 **> 0.8 米**；
   - 潜伴 **不足两人**；
   - 起返压 **< 50 巴**（边界值 0.8 米 / 50 巴 / 两人正好放行）。
3. **换人复核**：标记保存后恒为「待复核」；复核人必须是本潜次主潜员与两名潜伴之外的**第三人**，并须再次核对实际出水时间（与闭潜记录一致）。**复核通过后标记才计入潜次时间线**。
4. **潜次改动即失效**：修改已登记潜次的任一安全相关字段（编号、人员、时段、潮高、起返压）后，其全部关联标记**立即失效**，旧值写入留档（可在「留档」视图追溯），**不再导出 JSON**，且该潜次需重新闭潜、标记需重新登记与复核。已通过复核的标记被再次编辑时，复核结论同样撤销、回到待复核。

## 界面

- 左侧沉船平面图：点击落位，虚线黄框＝待复核，绿圈＝已计入时间线，灰显＝已失效。
- 右侧四个视图：**标记 / 潜次 / 时间线 / 留档**。
- 顶部三个筛选（类型、状态、潜次）对地图、列表、时间线、统计和导出同时生效，刷新后保持不变；「刷新数据」从本地存储重载并保持筛选。
- 「导出 JSON」只导出未失效标记及关联潜次，文件中包含当前筛选条件与安全阈值；失效标记仅保留在本地留档中。

## 分层结构

| 文件 | 职责 | 不允许包含 |
| --- | --- | --- |
| `js/rules.js` | 全部业务规则与状态流转：登记校验、安全闸门、闭潜、换人复核、失效、筛选、时间线、统计、导出 | DOM、localStorage |
| `js/storage.js` | localStorage 持久化、版本化、旧版数据迁移、示例数据、界面偏好 | 阈值与流转判定 |
| `js/app.js` + `index.html` | 输入、调用规则层动作、持久化并渲染 | 自定义安全阈值/绕过规则的判定 |

规则层为纯函数（不可变状态：每个动作返回 `{ok, errors, state}`），可直接在 Node 下测试，见 `test/rules.test.js`。
