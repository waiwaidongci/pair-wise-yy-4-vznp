# 水下考古潜水记录 · 潮汐窗口与安全余压闭环

直接打开 `index.html` 使用（无构建、无运行时依赖）。数据保存在浏览器 `localStorage`。

## 闭环流程

1. **潜次登记**：每个潜次登记计划时段（开始/结束）、两名潜水员、起始压力与返回余压、潮高，出水后补登实际出水时间。
2. **安全门槛（闭潜前置）**：
   - 潮高 `> 0.8m` 不得闭潜（0.8m 整视为合格）；
   - 潜伴不足两人不得闭潜（去空白、去重后计数）；
   - 返回余压 `< 50 巴` 不得闭潜（50 巴整视为合格）。
   任一不满足时，关联标记**只能停留在“待复核”**，“登记闭潜”被拒绝。
3. **标记复核**：复核**须换人**（复核人不能是该潜次两名潜水员中的任何一人），并勾选**已核对实际出水时间**；存在阻塞项时通过按钮禁用。通过后标记才**计入潜次时间线**。
4. **改动即失效**：一旦改动潜次登记字段，关联的未失效标记**立即失效**；旧值留档（潜次 `history` 版本快照、失效标记原样保留），但**不再导出**、不计入统计与时间线。编辑未失效标记会让已通过的复核作废、回到待复核；已失效标记不能编辑也不能复活。
5. **导出 JSON**：只导出现行值——已失效标记排除、潜次留档 `history` 排除。
6. **一致**：地图、列表、时间线、统计共用同一筛选结果（类型 + 状态）；筛选条件与当前潜次随刷新恢复。

## 三层结构

| 文件 | 职责 | 依赖 |
| --- | --- | --- |
| `js/rules.js` | 全部业务规则：门槛判定、复核校验、失效、统计、导出内容 | 无 DOM、无存储，纯逻辑 |
| `js/storage.js` | `localStorage` 读写、演示数据、旧版数据迁移、潜次留档记账 | 不做业务判定 |
| `js/app.js` | 渲染与交互；判定调规则层，读写调存储层 | DOM |

数据键：`zfl30.diveLog.v2`（潜次与标记）、`zfl30.diveLog.ui`（筛选/视图偏好）；旧版 `zfl30Marks` 首次打开时自动迁移。
